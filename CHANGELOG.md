# Changelog

## [Unreleased]

### Breaking Changes

- Replaced the embedded Jellyfin Web client with MediaFlick Desktop's own UI. The app no longer loads jellyfin-web at all: it now signs in against the Jellyfin server itself and serves its own login, home, library, and details views from `mediaflick-desktop://app/`. Existing users keep their configured server URL and must sign in once on the new login screen; browsing, searching, and starting playback all happen in the new UI. Server administration is not rebuilt and opens in the system browser through the new "Open Jellyfin dashboard" context-menu item.
- Removed the jellyfin-web injection bridge (`bridge.js` and its stream-URL interception). Playback is now negotiated natively through `PlaybackInfo` and handed to mpv/MPC-HC directly, so third-party scripts or workflows that relied on the injected `window.__mediaFlickDesktop*` playback hooks in jellyfin-web no longer apply. The remaining native About and update-toast dialogs use only the small shell bridge.
- Removed the welcome/setup screen. The server address is entered on the sign-in screen and the media player is configured in Settings.

### Added

- Added the anti-slop Oxlint plugin, enabled its full rule set for the React UI, and migrated the owned UI code and tests to comply without rule suppressions.
- Added Latest Movies and Latest Shows shelves immediately after Recently Added on the home screen. They sort each catalogue by release year and link to the matching newest-first library view.
- Added an in-app `/settings/*` dashboard with anonymous Client and Appearance pages, account-scoped Letterboxd and Seerr pages, a permanent sidebar entry, local drafts, and Save/Discard/Reset controls. Typed section PATCH endpoints now share a preference service with CEF, apply player/segment/scrollbar changes at runtime, and return normalized settings and platform capabilities.
- Added Appearance preferences for system/dark/light mode, signal/cobalt/amber/violet accents, compact density, artwork/backdrop intensity, and reduced motion.
- Added account-scoped Letterboxd public-profile connections in SQLite. Profiles accept usernames or canonical URLs only, are normalized to `letterboxd.com`, verified through bounded RSS requests, and support refresh, enable/disable, external open, and removal.
- Added connected Letterboxd members' latest ratings and written reviews to matching movie detail pages. The client matches public RSS entries by TMDB movie id, converts review HTML to bounded plain text, caches feeds for 30 minutes with stale fallback, and keeps slow profile requests separate from the local detail response.
- Added connected Letterboxd members' ratings and reviews to Seerr-discovered movie details, matched directly by TMDB movie id so friends' opinions are visible before a title is requested.
- Added the optional MediaFlick Companion server plugin for Jellyfin 10.11.11. It exposes a versioned, authenticated `/MediaFlick` API; keeps Sonarr, Radarr, and Seerr API keys on the server; provides an admin dashboard page with redacted keys and connection tests; refreshes a stale-preserving Sonarr/Radarr calendar every 15 minutes; and mediates Seerr calls as the mapped Jellyfin user, with opt-in first-use import. The plugin has independent build, test, deploy, CI, and draft-release packaging flows.
- Added Companion-side MDBList/TMDB administration and the Desktop `ratings-v1` fallback contract. Administrator secrets are Data Protection-encrypted and never returned; capability/status data is authenticated and redacted; MDBList lookups use bounded stable-ID batches, a durable shared cache with stale-while-revalidate and in-flight deduplication, and restart-safe quota/Retry-After backoff. TMDB remains preparation-only, and Desktop local credentials retain precedence over the server fallback.
- Added a Releases route with agenda and month views, per-release-type filters, stale-source warnings, local-library Play/Open actions, and film request actions. It uses the Companion calendar when available and falls back to Jellyfin's metadata-only Upcoming feed when the plugin is absent.

- Added a local SQLite catalog index (`library.db`) covering movies, series, seasons, and episodes, with FTS5 full-text search over titles and genres, dedicated indexed columns for TMDB/IMDb/TVDB ids, and a background sync thread that runs a resumable bootstrap, an incremental `DateCreated` sweep, and an hourly identity sweep that both mirrors watch state and drops items deleted on the server.
- Added the app's own UI on the `mediaflick-desktop://app/` scheme: sign-in, a home screen with a combined Continue Watching / Next Up row and a Recently Added row, a virtualized library grid with instant type-ahead search plus sort, genre, and watched filters, a details view with cast, seasons, and episodes, and mark-watched/favorite round-trips.
- Added a cinematic home-page billboard with real play, resume, progress, details, and My List actions; a dedicated My List shelf; paged mouse- and keyboard-friendly media rails; remaining-time labels; browse-all shortcuts; and a guided empty state.
- Added a native play path that negotiates `PlaybackInfo` with a device profile honoring the configured streaming quality, picks a media source, builds the direct-stream or transcoding URL, and hands the result straight to the playback coordinator. Episodes automatically continue with the next one when mpv reports end-of-file or mark-watched-and-next.
- Added a streaming-quality picker next to Play on the details view. It overrides the quality saved in Client Settings for the rest of the session without opening a dialog, so a single title can be watched at a lower bitrate over a slow connection and everything else keeps the saved default.
- Added an in-app player bar (position, pause/resume, stop, scrub) backed by a `/api/player/*` endpoint pair, plus an image proxy with a pruned on-disk poster cache that keeps the access token out of the DOM.
- Added `--library-stats` and `--library-sync-once` for headless verification of the cache without starting the browser shell.
- Added `scripts/cdp-eval.ps1` for evaluating JavaScript inside a running app window over `--remote-debugging-port`.
- Added a collapsible sidebar as the app's primary navigation, replacing the top header bar: the library search, Home, Movies, Series, and a new Favorites view, with the signed-in user and their server pinned at the bottom and sync-library and sign-out in the menu there. It collapses to an icon rail from the toggle or Ctrl+B and remembers that across restarts.
- Added the React UI toolchain in `ui/`: Vite, TypeScript, Tailwind CSS v4 (CSS-first, no config file), shadcn/ui on the unified `radix-ui` package, TanStack Query as the only state layer, react-router, and `@tanstack/react-virtual`. `build.rs` runs the bundle build and stages it into `OUT_DIR`, so `cargo build` stays self-sufficient and can never embed a stale bundle; `just ui` and `just ui-dev` are available for working on the UI alone.

It is served by a new `/api/item/{id}/media` endpoint that reads `MediaSources` from the server on demand, since codecs are deliberately not in the local cache. Long subtitle lists collapse after six tracks.
- Added external-database links to the details view. A menu next to the action buttons opens the item on IMDb, TMDb, or TVDB in the system browser. The UI only names a provider — `/api/item/{id}/external` looks the id up in the cache and builds the address itself, and offers no link where the provider has no page for that kind of item.
- Added a Play button to series and season pages, which previously offered none. A series starts its Next Up episode (falling back to the first episode once the show is fully watched or the server is unreachable), a season starts whatever was left half-watched, and both buttons name the episode they will start.
- Added `scripts/cdp-screenshot.ps1`, the screenshot counterpart to `cdp-eval.ps1`, for capturing the running app window over `--remote-debugging-port`.
- Added the foundation for requesting films and shows through Seerr (formerly Jellyseerr): its own REST client, error type, and storage. `POST /api/seerr/connect` probes an instance and refuses one whose setup wizard is unfinished — an uninitialized Seerr treats a login as its setup wizard and would make whoever logs in the instance owner — or one wired to something other than Jellyfin; `GET /api/seerr/status` reports whether a link exists along with the user's typed per-media-type request and auto-approve permissions and their quota. The link is the user's own session, never an instance-wide API key, and it is bound to the Jellyfin account it was made under, so signing out or switching users drops it rather than leaving one user's Seerr session serving another. Cookies are captured from the very first unauthenticated probe so a Seerr with CSRF protection turned on works from the first write onwards, and only GETs are retried, so a request can never be sent twice. No UI yet.
- Added `--seerr-status` for headless verification of the Seerr link without starting the browser shell.
- Added the Seerr link itself: `POST /api/seerr/link/password` signs in with the media-server password every Seerr release accepts — used once and never stored — and `POST /api/seerr/unlink` ends the session at the instance before forgetting it locally, keeping the address so re-linking does not mean retyping it. Because Seerr exposes no media-server identity before login, the account behind the session it hands back is checked against the Jellyfin account this app is signed in as, and a session belonging to anyone else is logged out again and never written to disk. A rejected password and a user Seerr has never imported now say so specifically instead of both reading as a generic failure, and neither is reported as an expired session.
- Added Seerr's read paths and the join that makes them useful: `GET /api/seerr/search`, `GET /api/seerr/discover/{trending|movies|tv}`, and `GET /api/seerr/media/{movie|tv}/{tmdbId}`. Every result is matched against the local cache on **(kind, TMDB id)** — never the id alone, since TMDB numbers films and series separately and the id 603 addresses two unrelated titles — so a result resolves either to the item you already have or to something you can request, with no dead ends. `person` results are dropped before the join. A `GET /api/seerr/image/{size}/{file}` poster proxy serves TMDB art through the existing pruned on-disk cache; as with the external-database links, the UI names a rendition size and a file and the shell builds the address itself, refusing anything that is not a plain TMDB token.
- Added a Discover view and the request flow: trending, popular films, and popular series as tabs, a Seerr-wide search box, and a request dialog with per-season selection on partial-request instances and a 4K toggle that only appears where both the instance and the user's own permission mask allow it. The dialog is shown even to users whose requests are approved automatically, and the toast reports which of the two actually happened. Seerr setup is a dialog off the user menu — probe the instance, then link, with the password step appearing only where the password-less path is unavailable — and the Discover and Requests entries stay out of the sidebar until Seerr is linked.
- Added rich Seerr discovery detail pages with summaries, external trailer links, cast, ratings, production facts, and regional release schedules. Users with Seerr's advanced-request permission can choose a quality profile from the linked Radarr or Sonarr destination before submitting a request.
- Added a quick-request plus action to Seerr discovery posters. It appears on pointer or keyboard focus, stays visible for touch pointers, skips detail navigation, and opens the existing request dialog only when the title still has a permitted regular, partial-series, or 4K request path.
- Expanded Discover with Seerr's upcoming-film and upcoming-series feeds, illustrated movie and series genre browsing, popular/rating/newest sorting, minimum-score filters, trending type and day/week controls, and a local-library visibility filter. Search now loads every result page as it scrolls instead of stopping after the first, and discovery cards show their TMDB match score plus an explicit Request or Open details action. The same allowlisted discovery contract is implemented by both direct Seerr sessions and the Companion plugin.
- Added a release-decade filter to Seerr's film and series catalogues. It composes with genre, rating, and sort controls, uses exact inclusive release/first-air date ranges (capped at today for the current decade), and keeps the selected tab and filters in the URL when opening a title and returning to discovery.
- Added a Requests view listing your own requests (never the household's) with approval and download-status badges, cancellation of ones still pending, and a link straight to the item once it has landed in the library. It refetches every 30 seconds while open and on window focus, and nothing polls in the background. Library search now ends in a "Not in your library" block fed by its own query, so local full-text results still render at SQLite speed and never wait on a round trip to Seerr, and titles the cache already holds appear once, from the cache. A series the library only partly has gains a "Request season" action on its details page.
- Seerr's overloaded 401 is now disambiguated. Seerr answers 401 both to a lapsed session *and* to a valid session that merely lacks a permission — cancelling somebody else's request is the case that proves it — so a 401 from any call is now confirmed against `/api/v1/auth/me` before it counts as an expiry. A refused action surfaces as a permission error and leaves the link alone; only a session that cannot answer for itself puts the UI into the re-link prompt.
- Added an expanding hover card over every poster and progress card, on the home screen and in the library grid alike. Resting the pointer on a card for a moment lifts a panel over it with the title's landscape artwork, its wordmark where the server has one, and round Play, My List, watched, and details controls, followed by the match score, maturity rating, year or season count, runtime, and genres. One panel exists for the whole app, it is drawn outside the shelves so it is never clipped by the row it belongs to, and it closes on scroll, on Escape, and on navigation. It arms only for a mouse, so dragging a shelf on a touchscreen cannot leave a panel behind.

After a still has established the title for five seconds, its trailer fades in muted when one is available — preferring a local Jellyfin trailer through the authenticated byte-range proxy and falling back to the privacy-enhanced YouTube trailer Jellyfin recorded for the movie. As playback begins, the trailer eases in as a full-height 16:9 panel flush with the banner's right edge — sized from the banner's height so the footage fills it exactly rather than floating inside it — while the backdrop stays full-bleed behind the title and only dims, with the trailer's left edge feathered into it instead of ending on a vertical seam or stretching the footage across the banner; YouTube's transient overlay is given time to disappear before that reveal completes, and its title and control regions stay cropped outside the banner. A slide's backdrop and trailer are fetched only when the rotation reaches it rather than all five up front.

The seed title and its series are left out of its own shelf, and the genre it used does not get a second shelf lower down.
- Title treatment artwork — a show's wordmark on transparency — is now served for every item that has one. The home billboard, the hover card, and the details hero draw it in place of the typeset title, and all three keep the text heading in the document for anything reading the page rather than looking at it. A missing or broken logo falls back to the heading.

It needs a Seerr newer than v3.3.0, which is the first release to carry the routes, *and* Quick Connect enabled on the Jellyfin server, which is off by default; with either piece missing the answer is simply "use the password", not an error. `POST /api/seerr/link/poll` finishes an attempt an instance has not caught up with yet.

### Changed

- Slimmed the local library cache to a thin catalog index and moved all rich metadata to live Jellyfin fetches. The cache now keeps one lightweight row per movie, series, season, and episode — identity, titles, year, runtime, community rating, hierarchy, provider ids, genres, and image tags — which is everything instant shelves, scrolling, sorting, filtering, counts, and provider-id joins need. Synopses, cast, critic scores, tags, and studios are fetched on demand by the detail page through a new `/api/item/{id}/about` endpoint, the billboard fetches its synopsis after the cached hero paints, and episode synopses ride along on the season page's existing live reconcile. Nothing from those fetches is persisted; when the server is unreachable these surfaces show plain loading/error states, which is the intended degraded behavior for an online client.
- Live title metadata now stays bounded by purpose: the billboard requests only a synopsis without user or image data, while detail responses keep the first 24 cast credits and a representative bounded crew list instead of mounting every person and headshot Jellyfin returns.
- Card quality badges (resolution, dynamic range, audio format) now arrive over a live batched channel modeled on the ratings scheduler: visible cards register, requests coalesce into bounded `/api/technical/batch` calls, and a batch is aborted once none of its cards remains visible. Badges appear for movies and series alike, fail silently offline, and stop being fetched entirely while Appearance hides media info.
- Library search results for a term that exactly names one Jellyfin person now include a live "Featuring" section with that person's movies and series, resolved over the same exact-identity path the cast pages use. Cast names are no longer indexed locally, and overview text is no longer searchable; title and genre search stays instant from SQLite.
- The full library re-page now runs daily instead of weekly. It is the only way in-place metadata edits on the server reach the thin index, and thin pages make it cheap.
- Bumped the library schema to 13. Per the pre-1.0 rule there is no migration: an older database is dropped wholesale and the catalog resyncs from scratch; only the signed-in session (and its device id) carries over, since it is what performs that resync.
- Rating readouts now use source-specific icons instead of abbreviated labels on cards, expanded hover previews, and title details, with distinct critic/audience marks and accessible full source names retained. Expanded previews also show the card's video/audio summary at a proportionally larger size.
- Appearance now controls whether technical video/audio information is shown on library cards, and its live preview mirrors a browsing shelf with the selected rating and media overlays. Editable preference fields consistently use Save/Discard/Reset, including the duplicate rating-source picker on the MDBList page.
- Connected Letterboxd profiles and movie review cards now show the member display name published in the profile's RSS channel title, while retaining the normalized username for profile identity and links.
- Replaced connected Letterboxd movie review cards with a compact cast-style profile rail: the local Letterboxd mark, five-position personal ratings, and display names stay visible, while bounded written reviews open on pointer hover or keyboard focus. Ratings and reviews are selected independently from the current RSS feed, so a newer rating-only rewatch no longer hides an older review that is still present.
- Renamed the right-click “Client Settings” shortcut to “Settings”; it now opens the React Player settings page rather than a native modal. Native file selection and mpv installation are request-correlated shell events owned visibly by the settings UI.
- Continue Watching now refreshes a stopped item from Jellyfin after its final playback report, so MediaFlick follows the server's configured resume thresholds instead of treating every non-zero position as resumable.
- Replaced misleading "% match" labels on browsing cards with familiar ten-point star ratings, making clear that they are community or TMDB metadata rather than personal recommendations.
- Removed the README's special AI-assistance disclosure; AI-supported development is treated as part of the normal project workflow rather than called out separately.
- Discovery tabs now fill the screen and continue loading titles automatically as the user scrolls, while retaining the separate Trending, Movies, and Series navigation.
- The home billboard now occupies half of the available content viewport instead of stepping through three fixed breakpoint heights, while retaining a minimum height on short windows so its controls remain usable. Its loading skeleton follows the same geometry, and the active player bar is accounted for automatically.
- Reworked the home billboard's backdrop-to-trailer blend from a straight vertical feather into a soft, asymmetric film-burn contour with subtle signal-green refraction along the overlap. The trailer now uses a slightly wider-than-16:9 stage and an earlier blend so the moving image gets more room without crowding the title.
- Seerr discovery, requests, status, and cancellation now use a provider abstraction. A compatible Companion plugin is preferred automatically, results are joined to the local library on the desktop, and the existing direct per-user Seerr session remains the fallback when the plugin is absent. Companion-mediated writes are never retried after an uncertain result, and Seerr permission failures cannot expire the Jellyfin login.
- Replaced the hand-written ES-module UI with a React application. The bundle is emitted with fixed `app.js`/`app.css` names and no code splitting — the assets are embedded in the binary and served from memory, so content hashing and chunking buy nothing — and `static_asset` embeds them from `OUT_DIR` instead of the source tree. Client-side routing moved from hash URLs to `pushState`, which the app scheme already supported.
- Building the app now requires Node and pnpm, and CI and the release workflow install both before the Rust steps. Set `MEDIAFLICK_DESKTOP_SKIP_UI_BUILD=1` to embed a bundle that was built out of band.

- The browser window now always loads `mediaflick-desktop://app/` instead of the Jellyfin server URL, and the shell only opens HTTP(S) navigations in the system browser.
- Added `rusqlite` (bundled SQLite with FTS5), pinned to 0.37 because 0.40's `libsqlite3-sys` build script needs a newer Rust than the project's toolchain.
- Raised the Jellyfin HTTP budget to 120 s with a 10 s connect timeout so full-metadata sync pages survive a remote server, while an unreachable address still fails fast on the sign-in screen.
- Rebuilt the details view, which showed only a small poster, a fact line, and the synopsis. It now opens with the item's own backdrop behind a larger poster, breadcrumbs from an episode back to its season and series, community and critic ratings, clickable genre chips, and a resume bar with the time remaining. Below it are a cast row with headshots and roles, a details panel with directors, writers, studios, premiere and added dates, play count and tags, and the new media panel.
- The details view now shows an item's backdrop whole, as a background for the whole page. It used to be cropped to the height of the hero — which threw away most of a 16:9 image — and what survived was dissolved into the page by a gradient running the full height of that block. The artwork is now painted at its own size behind every section of the page, so it reaches past the hero and the cast, seasons, and details draw over it; none of them move to make room for it. Two gradients are left: one scrim sized from the hero's own text, so the picture beside and below it stays untouched, and one wash that takes the artwork back where the page's content begins and ends it in the page colour rather than on a visible edge.
- The home screen's Next Up cards now share the Continue Watching row instead of sitting in a second row below it, so what to watch next is one carousel: half-watched items first, then the next unwatched episode of every other series. A show that appears in both lists — its in-progress episode is also its Next Up — contributes a single card.
- Continue Watching and Next Up now use wide 16:9 cards with episode stills or landscape title artwork instead of cropping every item into a portrait poster. Episode rows and episode detail pages keep the same landscape treatment.
- Carried the home screen's cinematic visual language through library browsing, search, discovery, requests, item details, sign-in, dialogs, empty states, and the player bar, with stronger page hierarchy, translucent surfaces, and consistent card motion.
- Gave the app a visual language of its own rather than the one every streaming service shares. A single bright green replaces the red, and every neutral is mixed toward it, so the shell reads as one material lit from a single source instead of a grey chassis with coloured buttons. Corners are near-square throughout — 2px around artwork, 4px on chrome — and nothing is a pill except a progress track. Every measured fact (runtimes, ratings, years, counters, shelf eyebrows) is set in a monospace face with wide tracking and divided by accent slashes, so a page separates into what a title is called and what is known about it before a word of it is read. Shelf headings open with an accent marker and run out to the page edge on a hairline. A hovered card is framed with corner brackets rather than enlarged, which keeps a shelf's rhythm intact while the pointer runs along it, and the expanded panel's controls are squares rather than circles.
- A watched title is now marked with a full-width finished progress rule along the foot of its artwork instead of a corner badge. It uses the same three-pixel thickness and bright accent fill as playback progress, keeping the state clear without covering the artwork.
- Episodes are now listed as rows with a 16:9 still, number, title, runtime, synopsis, and per-episode Play and watched controls, instead of as 2:3 poster cards with no text. An episode's own page shows its still at 16:9 rather than cropped into a poster frame. `/api/item/{id}/children` carries the overview for this, so the list costs no extra requests.
- Simplified the sign-in screen header to the MediaFlick logo, removing the placeholder film glyph, product eyebrow, slogan, and introductory copy.

### Fixed

- Fixed card clicks going dead when the press straddled the expanding hover panel's appearance. A mousedown on the card followed by a mouseup on the freshly mounted panel resolves the click outside both, so nothing fired; the panel now reads a release from a press it never saw begin as the card click it started as, and a pointer that arrives on a card mid-drag no longer arms the panel at all.
- Fixed expanded hover previews missing selected-source ratings because their portal was mounted outside the ratings context.
- Fixed a valid SQLite home cache flashing the full-page card skeleton at startup and again after route navigation. The startup cover now waits for the local home snapshot, cached shelves no longer wait on Jellyfin's live Next Up request or the independent billboard query, and those slower surfaces enrich the page without replacing cards that are already present.
- Updated ID generation to use the current `getrandom` fill API.
- Fixed discovery filter changes retaining stale leading cards or infinite pages from the previous result set. Every server-side filter and the local-library filter now gets one immutable result-set identity, filter changes abort and discard the prior infinite query, and React remounts the complete result wall instead of reconciling card-local state across sets. Release-decade choices now use consistent full labels and share a 1900 lower bound for films and series across the desktop and Companion contracts.
- Fixed an interrupted initial library bootstrap restarting from zero on its next attempt even though its page offset was stored. An incomplete pass now resumes from the last committed page, so the new item counter cannot jump backwards after a transient server or network failure.
- Fixed the first home screen opened after signing in showing only Continue Watching, without playback progress, until the app was restarted. Authentication queued the initial metadata bootstrap but mounted and cached the empty local home queries before that bootstrap ran; the authenticated loading gate now waits for the cache to be ready before any media route can read it.
- Fixed horizontally scrolling shelves and lifted cards painting across the sidebar boundary. The content inset now has a strict paint boundary and minimum width, the fixed sidebar owns the top stacking layer, and snapped shelves preserve their responsive left gutter at the start.
- Fixed the Seerr storage table never being created on a machine that had run a pre-release build from before the Seer/Seerr rename. That build stamped the database as being at the new schema version while creating the table under the old name, so the migration considered itself done and the renamed table never appeared — every Seerr read answered "no such table" and nothing could ever be linked. The schema now repairs such a database and drops the stale table, which no release ever carried.
- The Seerr client no longer follows redirects, and says plainly when it gets one. Seerr's API answers where it is asked, so a 3xx means a single sign-on proxy — authentik, Authelia, oauth2-proxy, Cloudflare Access — took the call before Seerr saw it. Following that redirect landed on a login page and, against an authentik outpost behind Cloudflare, died mid-way through its chunked HTML body and reported "could not reach Seerr: protocol: chunk expected crlf as next character" — a transport fault that says nothing about the real problem. Connecting now names the host the address redirects to and what has to change: exempt Seerr's `/api/` paths from the proxy, or use an address that reaches Seerr directly. MediaFlick signs in to Seerr with the user's own media-server account and holds no credential for a layer in front of it.
- A Seerr address that answers with something other than JSON now says so instead of reporting a JSON parser position. The commonest way the address is wrong is that it reaches a reverse proxy, a single sign-on page, or Seerr's own web front end rather than its API, and all of those answer 200 with HTML; "expected value at line 6 column 1" sent the user looking for a fault in Seerr rather than in what they typed. A body that really is JSON but the wrong shape is still reported as the decode failure it is. The body itself is still never logged or shown — only what the server called it and how big it was.
- Hardened Seerr session handling: API error logs no longer include upstream response bodies, poisoned locks retain their existing state, account changes cannot preserve a previous user's link, headless status probes cannot overwrite newer link changes, and Seerr authorization failures no longer masquerade as expired Jellyfin sessions.
- Fixed the incremental library sweep, which had never written a single row. It sorted and filtered on `DateLastSaved`, which is not a valid `ItemSortBy` value and which servers return empty, so every item compared as "not newer", the first page was cut to nothing, and the watermark was never stored. The cache therefore stopped changing entirely once the initial bootstrap finished — new and replaced items never appeared. The sweep now uses `DateCreated`, which is a valid sort key and is populated; because Jellyfin re-creates an item with a new id when its file is replaced, this also covers replacements.
- Added a weekly re-bootstrap that re-pages the whole library. Jellyfin exposes no usable "changed since" ordering, so this is what picks up in-place metadata edits to items that already exist.
- Cached items the server no longer has are now dropped as soon as it says so — a missing poster, a 404 from `PlaybackInfo`, or a missing item when fetching one directly — instead of lingering until the next sweep and offering a dead poster and a dead Play button. Because a poster can 404 on an item that still exists, that path confirms with the server before evicting anything, and a server that is merely unreachable never causes an eviction.
- Fixed a poster whose artwork has disappeared from the server re-requesting itself on every render; the card now falls back to the title placeholder after the first failure.
- Fixed a series or season page listing episodes that had been deleted on the server: they appeared as a wall of art-less placeholder cards with a dead Play button. Opening a series or season now reconciles its child list against the server before answering, so deleted episodes disappear and newly added ones show up immediately, instead of waiting for the next library sweep. - Added an external mpv IPC controller with command/event pipes, playback progress observation, pause/seek/stop support, and fullscreen mpv launch behavior.
- Added native Jellyfin Web player-control integration so play/pause, seeking, and playback state can control and reflect external mpv playback.
- Added bidirectional playback-state synchronization from mpv back into Jellyfin Web, including progress, pause state, stop/end handling, and saved resume position updates.
- Added bridge logging and synthetic media-readiness events so intercepted browser playback remains visible and debuggable.
- Added rotating app log files with configurable `--log-level`/`--log-file` options and redacted playback diagnostics.
- Added configurable mpv input bindings in `%APPDATA%\jellyfin-mpv\input.json`, including the default `w` binding to mark the current item watched and start the next queued item.
