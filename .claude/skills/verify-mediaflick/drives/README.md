# Shipped drives

What each drive in this directory proves, the flags it needs, and the evidence it writes. [SKILL.md](../SKILL.md) covers launch, the harness and evidence; [features/](../features/README.md) maps the user-facing behavior.

Shipped drives. All are proven on Linux, `segments` with every case on both backends (see [Playback](../features/playback.md)). On Windows 11 (2026-10-13) every drive shipped by then passes except `close-minimize`, `close-guard` and `segments`, `playback` on both backends; the close drives use `wmClose` and run on Linux only, and `segments` has not run there yet. Drives marked Linux below run only there, and drives run with `--account` need your own server (see [Your own server](../SKILL.md#your-own-server)):

- `smoke`: fresh profile, signed-out sign-in screen.
- `remote-keys` (Linux, needs `xdotool` and `xwininfo`): with the Built-in player, the app window is libmpv's and keys reach the page through the X11 keysym table in `src/shell/cef/libmpv_overlay/linux/input.rs`. The drive focuses the app window, sends real XTEST key presses for a TV/HID remote (XF86Back, XF86Forward, XF86HomePage, Menu, XF86AudioPlay, XF86AudioPause, XF86AudioStop, XF86AudioNext, XF86AudioPrev, and Right as the control) and records each `KeyboardEvent.key` the page saw in `remote-keys.json`. Read-only against the demo server.
- `startup-failure` (`--services-down --seed .claude/skills/verify-mediaflick/seeds/newer-accounts`): an `accounts.json` from a newer build makes the app's services refuse to open, so `/api/status` answers 503 (`--services-down` makes the in-session doctor expect that). The main window must still be shown, through the page's window-ready beacon, and the seeded file must stay as it was. Evidence: `startup-failure.json`, `services-down.png`.
- `login`: only through `just verify-login SERVER`. Quick Connect sign-in, approved by the user, then `saveAccount()`.
- `application-settings`: Settings → Application, draft, Discard, Save, `settings.json`, read-back.
- `browse`: sign-in, Home, Movies, search, movie and series detail, sign-out. Read-only against the demo server.
- `sign-in` (needs `--url https://demo.jellyfin.org/stable`): prefill, the Quick Connect probe while the Server field keeps focus, the code (never approved) and its copy button with a clipboard readback, user menu, sign-out from Home, remembered server.
- `home-library`: billboard ticks, shelf arrows, a card from Home, sort, a decade filter and its chip, an empty search, Favorites. Read-only.
- `detail-crew`: a movie's Crew rail (one `Director, Writer` entry with a loaded headshot, no crew lines left in Details), then a crew face to the person page listing the title they directed. Read-only.
- `item-detail`: movie extras and the More info menu (opened only), series seasons and episodes, an episode page and its Season breadcrumb. Read-only.
- `client-settings`: Player shelf per backend, range alert, leave guard, Playback select, restart notices, live scrollbar style, Restore defaults + Save, the Delete local account data dialog (cancelled).
- `labels`: the sign-in screen's Player and app settings link and Back to sign in, the save bar's Restore defaults and muted disabled Save, Favorites, the watched and favorites toggles on a movie and on episode cards, Countdown seconds gating, and the Releases startup option (opened, never chosen). Read-only.
- `close-minimize`: saves `Minimize window`, closes through the window manager and proves the window asked to be minimized while the app kept running; then saves `Exit MediaFlick` and proves the next close exits.
- `close-guard`: an unsaved draft, a window-manager close, the `Leave without saving?` dialog; `Keep editing` keeps the app and the draft, `Discard and leave` exits without writing it.

- `home-library-shelves` (demo server, or `--account SERVER`): Home's `Latest in <library>` shelves. After the first sync, Home settings list one `Latest in <name>` row per `/UserViews` entry, in its order, checked and under `Library`, as one block right after the built-in rows, and opening them leaves accounts.json's `home` as it was. Each library with titles has a shelf on Home whose ids are compared with Jellyfin's own answer for the library's profile: `/Items/Latest?ParentId=<library>&Limit=24` for grouped live kinds (music, music videos, books, home videos, photos, mixed, trailers); `/Items?ParentId=<library>&SortBy=DateCreated,SortName&SortOrder=Descending` (with `Recursive=true&IncludeItemTypes=BoxSet` for box sets) for box sets, playlists and Live TV; for a movies library `/Items?ParentId=<library>&IncludeItemTypes=Movie&Recursive=true&SortBy=DateCreated&SortOrder=Descending`; for a TV shows library each series' newest non-virtual episode `DateCreated` (else its own), computed from all of the library's series and episodes, which is how the cache sorts episode-added. Catalog shelves compare by sort key, so items whose keys tie may swap; the report lists the tie groups and whether the order was exact. `SortBy=DateLastContentAdded` is also read for TV shows and recorded as matching or not (it matched on both servers, 2026-10-17). A library with no titles must have no shelf. `/api/libraries/<id>/latest` must name the sort `episode-added` for a TV shows library and `added` for every other, one the library offers; each shelf's `All` link must be `/library/<id>?sort=<that sort>`, and pressing it opens that URL on the library. Then it turns the first shelf off and saves (accounts.json holds every library element in server order, that one `enabled:false`, and Home drops only that shelf), toggles another and presses Discard (the checkbox and accounts.json's SHA-256 return), and saves Restore defaults (every library element enabled, in server order, and the shelf back on Home). Every check is recorded in `home-library-shelves.json` (per library: name, kind, profile source, oracle query, shelf ids, oracle ids, match, the sort `/latest` named; the settings rows; accounts.json's `home` and SHA-256 before and after each step), with `01-home-settings`, one `02-home-shelf-NN` per shelf, `03-home-one-off`, `04-home-settings-reset` and `05-home-reset` screenshots. Writes only the profile's accounts.json, never the server.
