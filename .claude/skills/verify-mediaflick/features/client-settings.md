# Client settings

The Client group in Settings holds this device's Player, Playback and Application preferences. Every shelf edits a draft: changes stay unsaved until `Save`, `Discard` restores the saved values, `Restore defaults` loads defaults into the draft, and leaving a dirty shelf asks before discarding. Saved values land in `settings.json` in the config dir. Most keys are left out at their default value; `comfort` and `mark_watched_next` are always written, and `player_backend` is written once any Player save, `--mpv-path` on the command line, or a finished mpv install has set it (`src/preferences/model.rs`, `src/main.rs`).

## Sub-features

- `app-close` chooses what closing the window does (`Exit MediaFlick` or `Minimize window`) for the close button, Alt+F4 and, with the Built-in player, mpv's close key. External mpv binds its close key to stopping playback (`src/players/mpv/input.rs`).
- `app-scrollbars` shows or hides native scrollbars, applied as soon as it is saved.
- `app-loglevel` sets the log level for the next launch.
- `app-delete-local` deletes this device's data for the signed-in account (typed `DELETE`, then a confirmation dialog). The section is hidden when signed out.
- `app-recovery` shows a `Recovered local settings` notice on Application when a damaged settings file was replaced by its backup or by defaults (source-only).
- `player-backend` picks the built-in player (libmpv) or external mpv. Built-in shows comfort values and shortcut recorders; external shows the mpv path, `Installation help`, and on Windows the mpv installer.
- `player-shortcuts` records player keys, with a conflict alert that disables `Save`.
- `playback-quality` and `playback-segments` set the default streaming quality and intro/credits/recap/commercial skipping.
- `savebar` covers Save, Discard, Restore defaults and restart notices; `draft-guard` covers leaving with unsaved changes, by navigation or by closing the window.

## How to get to it (user POV)

- Signed in: sidebar `Settings` → lands on `Player` (`/settings/client/player`) → `Settings navigation` links `Player`, `Playback`, `Application`. The same navigation lists the Account group (`Viewing`, `Home`, `Appearance`, `Collections`) and Integrations (`MediaFlick Companion`, `Letterboxd`), which this file does not cover. Signed out, those links stay listed but are `aria-disabled`.
- Signed out: the sign-in screen's `Player and app settings` link. *Proven by `labels`.*

## Driving it with ctx (just verify)

Preconditions:

- Signed in through the sign-in form (`ctx.signIn`, demo server is fine: these settings are device-local).
- `ctx.readConfig("settings.json")` and `ctx.configStat("settings.json")` recorded before the change.
- Wait for `{ role: "combobox", name: "Player backend" }` before reading the Player shelf; while loading it shows only a `role="status"` `Loading settings…`.

- **Open the shelf.** `ctx.press({ role: "link", name: "Settings" })`, wait for `ctx.pathname()` to be `/settings/client/player`, then `ctx.press({ role: "link", name: "Application" })`. *Proven by `application-settings`.*
- **Draft.** `ctx.press({ role: "switch", name: "Show scrollbars" })`. `ctx.state(...)` reports `checked: true`, the save bar's status reads `You have unsaved changes.`, `{ role: "button", name: "Save" }` enables, and `settings.json`'s mtime is unchanged. *Proven.*
- **Discard.** `ctx.press({ role: "button", name: "Discard" })`. The switch returns to `checked: false`, the status text empties, and `settings.json` is still untouched. *Proven.*
- **Save.** Change the switch again, then `ctx.press({ role: "button", name: "Save" })`. A `Settings saved` toast appears (the Player shelf says `Player settings saved` instead), `settings.json` gains `"show_scrollbars": true`, `Save` disables, and `ctx.api("/api/settings")` reports `client.application.showScrollbars: true`. The page's `<style id="__mediaFlickDesktopScrollbarStyle">` (present while scrollbars are hidden) disappears without a restart. *Proven by `application-settings`, `client-settings`.*
- **Read back.** Press `Player`, then `Application` again: the switch still reads `checked: true`. *Proven.*
- **Restart notices.** A change that needs a restart replaces `You have unsaved changes.` in the status: `Log-level changes apply after restarting MediaFlick.` after `Log level`, and `Restart MediaFlick to switch player backends.` (or `… to enable the built-in player.`) after a `Player backend` change to or from `Built-in player`. *Proven by `client-settings`* (the log-level notice, and `… switch player backends.` when the saved backend is Built-in); `… to enable the built-in player.` is source-only. Saving such a change shows the toast `Player saved. Restart MediaFlick to apply the built-in player configuration.` instead of `Player settings saved`, in both directions (observed in a maintenance run).
- **Restore defaults.** `Restore defaults` loads defaults into the draft; `Save` then removes the Application and Playback keys from `settings.json` instead of writing defaults. *Proven by `client-settings`.* On Player, `Save` after `Restore defaults` removes `default_fullscreen` but keeps `player_backend`, `comfort` and `mark_watched_next`, and the toast reads `Player settings saved`. *Proven by `player-shelf`.*
- **Selects.** Selects are Radix comboboxes named by their `label` prop, not the visible row title: `ctx.choose({ name: "Close behavior" }, "Minimize window")`, `ctx.choose({ name: "Log level" }, "Info")`, `ctx.choose({ name: "Player backend" }, "External mpv")`, `ctx.choose({ name: "Default fullscreen" }, "Windowed")`, `ctx.choose({ name: "Default streaming quality" }, …)` (`Original file`, `Auto`, `120 Mbps` … `1.5 Mbps`), and the segment selects `Intro skipping`, `Credits skipping`, `Recap skipping`, `Commercial skipping` with options `Never`, `Ask me`, `Always skip`. `Log level`, `Player backend` and `Intro skipping` (`settings.json` `skip_intro: "always"`) are *proven by `client-settings`*, `Default fullscreen` (`default_fullscreen: "windowed"`) by `player-shelf`; the others are source-only.
- **Player, built-in.** `ctx.api("/api/settings")` reports `capabilities.libmpv` (on Linux, whether `libmpv.so.2` loads, or a file exists at `MEDIAFLICK_DESKTOP_LIBMPV_PATH` or beside the executable) and `capabilities.mpvInstaller` (Windows only). A fresh profile on Windows and Linux reads `Built-in player` whether or not libmpv loaded (`PlayerBackend::platform_default`); without libmpv the option is disabled and `Restore defaults` picks `External mpv`. With libmpv available, the shelf has a subtitle preview, six spinbuttons (`Subtitle size (%)`, `Subtitle outline`, `Subtitle background (%)`, `Subtitle vertical position`, `Seek backward seconds`, `Seek forward seconds`, each with a `… slider`) and nine shortcut recorders named like `Pause key` (`aria-pressed` while recording) with `Clear pause key`. A value out of range shows `role="alert"` `Enter a whole number from 50 to 200.` and disables `Save`. *Proven by `client-settings` on Linux.*
- **Shortcut conflict.** Press `{ role: "button", name: "Pause key" }` (it reports `pressed: true` while recording), then `ctx.key("m", { code: "KeyM", keyCode: 77 })`, the Mute key's default: `role="alert"` reads `Assign each key combination to only one action.` and `Save` disables. A key that clashes with `Mark watched key` reads `This conflicts with the mark watched key. Assign each key combination to only one action.` (source-only). *Proven by `player-shelf`.*
- **Player, external.** `External mpv` shows `{ role: "textbox", name: "mpv executable" }`, `{ role: "button", name: "Choose mpv executable" }`, `Installation help`, and the only shortcut recorder left, `Mark watched key`. The `Install mpv` button exists only where `capabilities.mpvInstaller` is true; on Linux the row titled `Install mpv` holds just `Installation help`. *Proven by `client-settings` on Linux.*
- **Leave guard.** With a dirty shelf, press another settings link: `{ role: "dialog", name: "Leave without saving?" }` offers `Keep editing` (stays) and `Discard and leave` (drops the draft and navigates). *Proven by `client-settings`.* The guard also fires on sidebar links that leave Settings (source: `useBlocker` blocks any path change; not driven).
- **Close behavior on a window close (Linux).** Save `ctx.choose({ name: "Close behavior" }, "Minimize window")`, then `ctx.wmClose()`: `iconifyRequested` is `true`, `ctx.appExit(5000)` is `null`, and `ctx.appLog()` contains `close request minimized the window`. With `Exit MediaFlick` saved, `wmClose()` reports `iconifyRequested: false` and `ctx.appExit(20000)` returns the exit. *Proven by `close-minimize`, with the Built-in player and with External mpv.*
- **Leave guard on a window close (Linux).** With a dirty shelf, `ctx.wmClose()` opens the same `Leave without saving?` dialog. `Keep editing` keeps the app running and the draft unsaved; `Discard and leave` exits (`ctx.appExit`) and `settings.json` does not gain the draft. *Proven by `close-guard`, with the Built-in player and with External mpv.* `app.log` shows `page asked to confirm leaving forced=false` for each attempt (observed, not asserted).
- **Delete local account data.** Typing `DELETE` into `{ role: "textbox", name: "Type DELETE to confirm local account deletion" }` enables `Delete local account data`; pressing it opens `{ role: "alertdialog", name: "Delete local account data?" }` with `Cancel` and a second `Delete local account data`. Only the dialog's action deletes. *Cancel proven by `client-settings`.*
- **Proof.** Snapshot the draft state (`02-draft.ax.txt` in `application-settings`), screenshot each state, and keep `settings-before.json`, `settings-after.json` and `settings-final.json` via `ctx.writeEvidence`.

## Gotchas

- `role="status"` gets no accessible name from its content, so read the save bar text with `ctx.app.evaluate('document.querySelector(".settings-save-bar [role=status]")?.textContent')`.
- The save toast (`Settings saved`, or `Player settings saved` on Player) sits over the save bar's buttons for about 4 s. `ctx.press` waits it out; a hand-rolled click would hit the toast.
- End a drive with the shelf saved or discarded. A dirty draft answers teardown's `window.close()` with the leave dialog, and teardown has to force the exit.
- End a drive with `Exit MediaFlick` saved. With External mpv, teardown's `window.close()` otherwise minimizes the window and teardown has to force the exit.
- A drive that closes the app on purpose ends with `exit: exited-early` in `result.json`; the drive's own `appExit` check is the proof.
- Signed out, Settings navigation shows `Back to sign in` above the shelf list, and the sidebar user menu still reads `Signed in`; leave through `Back to sign in`.
- Never press `Installation help` (opens the user's default browser on the visible desktop), `Install mpv` on Windows (downloads and installs mpv into the profile), `Choose mpv executable` (opens a native file dialog on the private display that no drive can answer), or the dialog's `Delete local account data` (wipes the profile's account and signs out mid-drive).
- `Show scrollbars` is also passed to CEF at launch, but the saved value and the style element are the proof, not what the page's scrollbars look like.
- `Restore defaults` only loads defaults into the draft; it still needs `Save`. On Player it also clears the mpv executable path, so after an External mpv run `Save` removes `mpv_path` too.
- `settings.json` also gains `jellyfin_url` after sign-in and `webui_window` once the window moves or resizes; leave both out of before/after comparisons.
- The leave dialog has two more forms: `Saving settings…` (leave button disabled) while a save is in flight, and `Leave settings?` with `Leave page` for a blocked window close with nothing dirty (`SettingsDraftGuard.tsx`). A drive that saves and ends at once can hit the first: wait for `Save` to turn disabled before the drive returns, or teardown ends `forced`.
- The next-episode countdown is not a client setting: it is Viewing's `Next episode` and `Countdown seconds`, stored per account in `accounts.json` (see [Account settings](./account-settings.md)).
- External mpv for a drive: `--seed` a `settings.json` holding `{"player_backend":"mpv","mpv_path":"/usr/bin/mpv","default_fullscreen":"windowed"}` (`seeds/external-mpv/`). Fullscreen mpv covers the app window; see [Playback](./playback.md).
