### Added

- When `library.db` cannot be used at startup, because a newer MediaFlick wrote it or its update failed, the startup error screen now offers **Open data folder**, which shows the folder holding it in your file manager, and **Recreate library**. Recreate library asks first and says what you lose and keep. Confirming it renames `library.db`, `library.db-wal` and `library.db-shm` in the same folder to `library-replaced-<date>-<time>Z.db`, `library-replaced-<date>-<time>Z.db-wal` and `library-replaced-<date>-<time>Z.db-shm`, with one UTC date and time for all three (for example `library-replaced-2026-11-19-183436Z.db`), without deleting anything. MediaFlick then continues in the same window on a new, empty library: you sign in again, Jellyfin lists MediaFlick as a new device, and the library syncs again. Your settings, Letterboxd profiles, collections and their posters, audio and subtitle choices, and reading positions are kept. Cached ratings and the titles in your collections refill through the Companion, which spends MDBList and TMDB requests, and a collection set to refresh manually stays empty until you refresh it. Cancel changes nothing, and MediaFlick never recreates the library on its own. When another program is using `library.db`, the screen offers neither button: it says so and asks you to close that program and restart MediaFlick, since moving a database another program has open can damage it.
