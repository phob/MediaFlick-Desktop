# 0007. Embedded UI runs on a custom CEF scheme with strict origin, CSP, and thread boundaries

Status: Accepted (2026-11-22). Consolidated from codebase audit of `src/shell/cef/`, `src/app/`, `src/windows/`, and `ui/src/`.

## Context

MediaFlick embeds a React SPA inside CEF while keeping native file access, playback, OS integration, and Jellyfin credentials in Rust. The shell must expose a same-origin API and HTML5 history without binding a localhost HTTP port, keep page input from invoking arbitrary native URLs or scripts, respect CEF's UI/IO/background thread rules, and handle platform quirks on Windows, Linux, and macOS.

## Decision

- **Custom scheme and routing.** `mediaflick-desktop://app/` is registered with `STANDARD | SECURE | CORS_ENABLED | FETCH_ENABLED` so `fetch()`, CORS, and `createBrowserRouter` (`pushState`) work with real origin semantics without a local HTTP port. Unknown non-API paths serve `index.html`.
- **Content Security Policy and external links.** The app CSP restricts scripts and styles to `'self'`, permits `blob:` only for book-reader media/styles/fonts/frames (never `script-src`, because blob documents inherit CSP), and limits remote frames solely to `https://www.youtube-nocookie.com`. `open_external` accepts only a named `ExternalProvider` enum and builds fixed-host URLs from cached, validated IDs—never a URL string from the UI. YouTube trailer embeds never load YouTube's remote IFrame JS SDK; the UI speaks raw origin- and source-checked `postMessage`, while CEF injects `http://localhost/` (`NEVER_CLEAR_REFERRER`) on initial `youtube-nocookie.com/embed/` requests to avoid YouTube error 153 on custom schemes.
- **Bridge and window-reveal boundary.** Native toast actions over `mediaflick-desktop://<action>` require a CSPRNG per-session token (failing closed with process exit if OS CSPRNG fails) plus a trusted origin. Because the main window starts hidden until React unmounts `LoadingScreen` and paints (using a 100 ms fallback beside two `requestAnimationFrame` ticks when `--hidden` throttles rAF), `windowReady` uses the normal API queue and falls back to an app-origin-only `mediaflick-desktop://window-ready` image beacon (accepting Chromium's trailing-slash normalization) when startup failure leaves the API queue down. `on_load_end` reveals `data:text/html` error pages directly, and `window.show()` is followed by `window.activate()` because launch foreground rights have expired.
- **Threading and cancellation.** App-scheme API handlers execute synchronously on CEF's background thread (safe for SQLite and HTTP) while `ResourceHandler::cancel` fires concurrently on CEF's IO thread via a shared `AtomicBool`. UI-thread-only work (file dialogs, window reveal, preference apply plans, player rebuilds) crosses through `ShellBridge` / `post_task(ThreadId::UI)`; pre-subscribe events are safely dropped because no browser page exists yet. Windowless CEF has no native `beforeunload` dialog and blocks the renderer until answered, so `on_before_unload_dialog` cancels unload and broadcasts `WindowCloseBlocked` unless a forced close is active.
- **Desktop surface and platform bootstrap.** The UI blocks browser accelerators (`Ctrl/Cmd+P/S/U/R/-/=/+/0`, `F5`, Chromium `F7` caret browsing, `{ passive: false }` `ctrl+wheel` pinch zoom, drag-drop navigation, and auxiliary mouse button 3/4 double-stepping) and sets native selection/cursor defaults outside editable inputs. `main` bypasses `Cli::parse()` when `--type` marks a CEF subprocess, calls `cef::api_hash` before other CEF calls, and overlaps `Services` init on a background thread with `cef::initialize`.
  - **CEF bindings (`cef-rs`).** `PostData::elements` requires a pre-sized `Vec` (`len()`, not capacity); `run_file_dialog` must pass `Some(&mut filters)` even when empty (null crashes on Linux/macOS); `linux_desktop_id` forgets its owning `CefString` for `cef-rs`'s borrowed-string callback trampoline; `with_standard_window_buttons` returns `1` because `cef-rs` defaults omitted callbacks to `0`.
  - **Windows.** `--in-process-gpu` avoids Windows GPU subprocess `STATUS_BREAKPOINT` crash loops; CEF OSR lacks XBUTTON support so `WM_XBUTTONUP` navigates while down events are consumed; `DEVMODEW.dmDisplayFrequency <= 1` maps to 60 Hz; `%COMSPEC%` is shimmed to `current_exe()` (`CREATE_NO_WINDOW`) so mpv Lua `os.execute` does not flash consoles; a process-lifetime `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` handle terminates child players on crash/exit; `WM_SETICON` applies `winresource` ID `1` so libmpv's HWND does not show mpv's icon.
  - **Linux.** `libcef.so` must precede `libc` via `LD_PRELOAD`/`LD_LIBRARY_PATH` without persisting shell env; unpackaged launches register an `X-MediaFlick-Generated=true` `.desktop` entry before window creation (preferring `$APPIMAGE` over FUSE `current_exe()`, absolute `Icon=` path, `/bin/sh -c 'exec "$0"'` wrapper against `=` in paths, yielding to user/system entries) so Wayland resolves the app icon.
  - **macOS.** CEF framework loads dynamically (`../Frameworks` in main app, `../../..` in helper bundles; dev builds self-spawn); `+[MediaFlickApplication sharedApplication]` runs before CEF touches `NSApp` to install `CrAppProtocol` (`isHandlingSendEvent`) and override `terminate:` (preventing AppKit's immediate `exit()`) backed by a main-thread `thread_local` `EXIT_STATE`.

## Rejected alternatives

- Localhost HTTP server for the UI/API: opens a local port, complicates auth/CSRF, and weakens origin isolation.
- Hash routing or loading YouTube's remote JS SDK into the privileged page: unnecessary once the custom scheme is `STANDARD | SECURE | FETCH_ENABLED`, and remote scripts violate the strict `'self'` CSP.
- Allowing arbitrary URLs through `open_external`: lets renderer bugs launch arbitrary OS handlers or local files.

## Consequences

- CEF handles HTTP `Range` headers itself against custom-scheme handlers, so ranged readers that return only a chunk must pass bounds as query parameters (see [0014](0014-embedded-book-reader-and-archive-wasm.md)).
- CDP's `Fetch` domain does not intercept `mediaflick-desktop://`, so E2E harnesses wrap `window.fetch` instead (see [0016](0016-release-packaging-and-verification-harness.md)).
- Any change to CEF's threading, window-reveal, or CSP rules must preserve startup error-screen visibility when native services fail to open.
