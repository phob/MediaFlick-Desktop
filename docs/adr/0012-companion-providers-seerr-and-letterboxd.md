# 0012. Companion provider integrations, Seerr joins, and direct public Letterboxd RSS

Status: Accepted (2026-11-22). Consolidated from codebase audit of `plugin/`, `src/companion/`, `src/integrations/`, `src/seerr/`, and `ui/src/`.

## Context

Provider features (Discover, Requests, Calendar, Collections, Ratings, and Letterboxd reviews) span Jellyfin's .NET plugin host, five upstream APIs (Seerr, Sonarr, Radarr, MDBList, TMDB), version skew between Desktop and installed Companion plugins, and public Letterboxd RSS feeds. Extending [ADR 0004](0004-companion-trust-boundary.md), each upstream imposes protocol and compatibility constraints that are not inferable from the code alone.

## Decision

- **Companion host serialization, ABI floor, and capability gating.** Jellyfin's host ASP.NET MVC serializer forces PascalCase, so typed Companion responses opt into `CompanionJson.CamelCase`; `POST admin/config` returns `200 { saved: true }` because `configPage.html` uses `ApiClient.ajax({ dataType: 'json' })`. `plugin/package.py` derives `targetAbi` from the compiled `Jellyfin.Controller` NuGet version (`<version>.0`, matching Desktop's `MINIMUM_SERVER`), and pads 3-part versions to 4 parts to match .NET `System.Version` ordering. Because older Companion builds silently ignore unknown query params, Desktop gates features on versioned capabilities (`seerr-discovery-v4` for `decade` vs superseded `v3` century, `seerr-discovery-v5` for studios/networks) and keeps newer Seerr DTO fields (`activity`, `externalIds`, `studioRefs`/`networkRefs`, `crew`) optional. After a 404 on `/MediaFlick/info`, a failing `/System/Info/Public` diagnostic probe is logged and ignored so the probe still resolves as plain "not found".
- **Provider credential health and cache locking.** MDBList and TMDB share one health policy (`ProviderHealthPolicy`): only 401/403 on credential-checking requests invalidates a key, while transport/5xx errors apply exponential backoff and preserve a valid key. MDBList returns 401/403 for private lists (must not invalidate the key) and authenticates keys before rate-limiting (so 429 on validation proves the key valid). Per-request 4xx outcomes (`RequestFailed`) mark a service healthy because they prove reachability and key acceptance. `MdbListHttpTransport` and `TmdbHttpTransport` avoid `IHttpClientFactory` (whose default logging can record query-param API keys) and never log `HttpRequestException` messages; `RestrictKeyRingPermissions` degrades gracefully on NAS mounts lacking Unix file modes. `ProviderCacheStore` serializes disk writes on an outer `_writeLock` while taking only a brief inner `_lock` to snapshot JSON, preventing out-of-order overwrites without blocking readers. `JsonRead` reads upstream JSON type-tolerantly and parses numbers via `ToJsonString()` to behave identically across parsed `JsonElement` and constructed `JsonValue` nodes.
- **Seerr, Sonarr, Radarr, MDBList, and TMDB constraints.**
  - *Seerr:* `/api/v1/status` is public, so connection tests authenticate `/api/v1/auth/me` first; `/user/import-from-jellyfin` requires dashless `"N"` GUIDs; `combined_credits` deduplication prefers rows carrying `mediaInfo`; `created_by` relays unmapped snake_case `profile_path`; `advancedRequest` maps to `REQUEST_ADVANCED`; omitted `seasons` requests the whole show; studio discovery works only on movies and network discovery only on TV; list results omit per-season status (making `partial` actionable only for TV); request rows omit titles/artwork (resolved via per-title `useSeerrMedia`).
  - *Seerr + *arr activity & calendar:* Seerr's coarse `processing` state is refined with precedence: live `downloadStatus` -> Radarr release status / Sonarr monitored-episode counts (`episodeCount` counts aired/filed monitored episodes only; Companion connects only to regular-quality *arr instances, so file counts cannot decide 4K activity). Sonarr's `/api/v3/calendar` requires explicit dates (`1900-01-01`..`2100-01-01` fetches all episodes in one call like Radarr's `/api/v3/movie`), requiring a 64 MiB response cap vs Seerr's 16 MiB; Home combines daily calendar `hasFile` with local `libraryItemId` to reflect recent downloads.
  - *MDBList & TMDB:* MDBList list fetches use full payloads (`limit=500`) rather than `ids_only` because `ids_only` drops `rank` and moves TMDB IDs. TMDB movie, TV series, and episode numeric IDs are separate namespaces (joins and links must qualify by kind; episodes never link to `/tv/{id}`). TMDB caps search at 500 pages, lacks a TV network search endpoint (Companion ships a curated static network list cached with `staleTime: Infinity`; `NetworkSelect` injects a synthetic option for uncurated IDs), does not guarantee chronological collection parts (sorted explicitly by `release_date`), and needs `voteCountGte=50` for `vote_average.desc`. Desktop shares the pruned Jellyfin image disk cache with `IMMUTABLE_CACHE` for TMDB filenames.
- **Local catalog join and live person ownership.** Native Rust joins Seerr results against SQLite (`libraryItemId`), suppressing all duplicate `(mediaType, tmdbId)` rows for owned titles; local ownership overrides Seerr `unknown` without blocking `partial` TV or 4K requests. For person credits, progressive sync makes SQLite incomplete and Jellyfin truncates cast lists: when a Jellyfin `personId` is known, Desktop clears provisional `libraryItemId`, runs a live Jellyfin person pass, and verifies unmatched SQLite TMDB candidates live via `/Items?ids=` (`libraryExtras`), failing only the Discover section on error; without `personId`, UI waits for `catalogComplete`. Discover URLs carry studio/network `name` only for filter chips (only `id` goes to Seerr), key results on scalar `resultSetKey` including post-join `availability`, deduplicate across infinite-scroll pages, and keep the pagination sentinel rendered when client filtering empties a page.
- **Direct public Letterboxd RSS.** Letterboxd profiles require no credentials and expose public RSS feeds on `letterboxd.com`, so Desktop fetches them directly (fixed host, 512 KiB byte cap, CDATA HTML stripped in Rust so untrusted HTML never reaches React, refused for non-Movie items due to TMDB movie-only `movieId`). Feeds are ordered newest-first and track newest rating and newest written review independently; failed verification probes save `Unverified` rather than rejecting input so users can retry without retyping. Built-in collection templates in `src/collections/templates.rs` are independently authored.

## Rejected alternatives

- Using `IHttpClientFactory` for query-parameter API keys (MDBList/TMDB v3): risks logging secrets in request URIs.
- Routing public keyless Letterboxd RSS through Companion: would require Jellyfin 12.0 + Companion for a public feed with no credentials.
- Merging local SQLite FTS search with Seerr/TMDB search into one blocking query: couples instant local search to external network latency.

## Consequences

- Older Companion plugins continue working with newer Desktop releases as long as new optional fields and capability checks remain additive.
- Jellyfin 12.0 lists plugins skipped due to `targetAbi` as `Active` in `/Plugins`, so E2E verification must confirm both the server load log and live `/MediaFlick/info` responses.
